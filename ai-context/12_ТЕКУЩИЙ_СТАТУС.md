# Текущий статус проекта

Дата: 5 сентября 2026

- Email/password login и register с подтверждением email

- Защита `/dashboard`, серверная проверка пользователя и logout
- `/login`, `/register`, `/forgot-password`, `/reset-password`

Безопасность:

- Service Role Key не используется в клиентском коде
- Токены не сохраняются вручную в localStorage или собственных cookies
- `/dashboard` защищён middleware и серверной проверкой
- Recovery callback принимает только фиксированный внутренний переход `/reset-password`
- Каталог доступен на чтение только для активных сущностей через RLS
- Пользовательские таблицы используют `auth.uid()` в RLS
- Ingestion Edge Function требует JWT и `app_metadata.ingestion_enabled=true`
- Демоданные не используют реальные учётные данные маркетплейсов

Окружение:

- Проект не запускается локально; целевая проверка — GitHub Actions и Vercel Preview.
- CI использует `npm ci` и Node.js 22.
- Production-домен `wobuy.ru` пока не подключён к Vercel.
- Прямой Vercel-коннектор в текущей сессии недоступен; deployment проверяется через GitHub status.

Текущий этап: полная механическая ревизия демо-продукта перед ручным E2E-тестом auth и кабинета.

В работе:

- Финальная проверка всех кнопок, ссылок, меню и внешних переходов
- Ручной E2E-прогон регистрации, подтверждения email, логина, восстановления пароля, избранного, поиска и кабинета
- Проверка UX на desktop/mobile после стабилизации CI

Не начинали:

- Реальные API Ozon/Wildberries/Яндекс Маркета
- Полнотекстовое и семантическое ранжирование
- pgvector и embeddings
- AI-агенты анализа товаров/отзывов

Перспективные улучшения после демо-стабилизации:

- Единый `Product Intelligence Score`: цена + качество + отзывы + доставка + надёжность продавца с объяснением вклада каждого фактора.
- История изменения цены и автоматический «реальная ли скидка» — сильный differentiator для wobuy.
- Saved Search 2.0: пользователь задаёт условие, а система отслеживает цену/наличие и сообщает только при достижении порога.
- Семантический поиск с pgvector: запросы вида «нужна лёгкая палатка для дождя до 15 тысяч» должны превращаться в структурированные критерии без сложных фильтров.
- Агентная архитектура после подключения источников: отдельные агенты для цен, отзывов, доставки и anti-fake, затем финальный decision-agent.
- Наблюдаемость ingestion: SLA по источникам, freshness, процент ошибок, дедупликация и контроль деградации данных.
