# Текущий статус проекта

Дата: 4 сентября 2026

Статус: Фундамент проекта и Supabase Auth стабилизированы; CI зелёный. Auth-страницы переведены на утверждённый V2-дизайн, восстановление пароля работает через реальный Supabase Auth flow. Устаревшие макетные версии auth-страниц удалены.

Готово:

- Next.js 15 + App Router, TypeScript, Tailwind CSS, ESLint + Prettier
- Framer Motion для интерфейсной анимации
- Supabase SSR: browser/server clients, cookie-based SSR
- Email/password login и register с подтверждением email
- `/auth/callback` для PKCE/OAuth и recovery
- Защита `/dashboard`, серверная проверка пользователя и logout
- `/login`, `/register`, `/forgot-password`, `/reset-password`
- `/auth/login`, `/auth/register`, `/auth/reset` сохранены как совместимые redirect-маршруты
- Восстановление пароля V2 использует реальный `resetPasswordForEmail` и `updateUser`, без имитаций и `console.log`
- V2 auth-дизайн подключён к рабочим маршрутам
- Старые `maket/LoginPage.tsx`, `maket/RegisterPage.tsx`, `maket/ResetPasswordPage.tsx` удалены
- Безопасный recovery callback без произвольных redirect URL
- Русский auth UI и основные ошибки
- `.env.example` без секретов; Service Role Key не используется
- GitHub Actions: install, typecheck, lint, format:check, production build
- CI run #60 для auth V2 — успешно: все проверки и production build прошли
- `package.json` закрепляет Node.js `22.x`, чтобы Vercel не выполнял автоматический major upgrade
- Временные workflow автоматизации исправлений удалены
- Дизайн landing hero интегрирован в приложение

Безопасность:

- Service Role Key не используется в Next.js-приложении
- Токены не сохраняются вручную в localStorage или собственных cookies
- `/dashboard` защищён middleware и дополнительной серверной проверкой
- Recovery callback принимает только фиксированный внутренний переход `/reset-password`
- Ответ восстановления не раскрывает существование аккаунта
- RLS будет добавляться вместе с реальной схемой пользовательских данных

Окружение:

- Проект не запускается локально; целевая проверка — Vercel Preview.
- `package-lock.json` отсутствует, поэтому CI использует `npm install`.
- Для регистрации и восстановления в Supabase нужен Email provider и Redirect URLs Vercel Preview.
- Production-домен `wobuy.ru` пока не подключён к Vercel.

Текущий этап: Неделя 1–2 — каркас + Auth + лендинг. CI стабилен. Для полного пользовательского auth flow нужна ручная проверка письма подтверждения и recovery-ссылки в Vercel Preview.

Следующий этап: поиск и страница результатов по `maket/SearchResults.tsx`; затем схема данных, сбор данных, нормализация и AI-агенты. После базового поиска — RLS, rate limiting и production hardening.
