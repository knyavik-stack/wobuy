# Текущий статус проекта

Дата: 4 сентября 2026

Статус: Фундамент проекта и Supabase Auth стабилизированы; CI и Vercel Preview зелёные. Auth-страницы переведены на утверждённый V2-дизайн, восстановление пароля работает через реальный Supabase Auth flow. Устаревшие макетные версии auth-страниц удалены. Начата интеграция каталога с реальными данными Supabase.

Готово:

- Next.js 15 + App Router, TypeScript, Tailwind CSS, ESLint + Prettier
- Framer Motion для интерфейсной анимации
- Supabase SSR: browser/server clients, cookie-based SSR
- Email/password login и register с подтверждением email
- `/auth/callback` для PKCE/OAuth и recovery
- Защита `/dashboard`, серверная проверка пользователя и logout
- `/login`, `/register`, `/forgot-password`, `/reset-password`
- `/auth/login`, `/auth/register`, `/auth/reset` сохранены как совместимые redirect-маршруты
- Восстановление пароля V2 использует реальный `resetPasswordForEmail` и `updateUser`, без имитаций и `console.log`
- V2 auth-дизайн подключён к рабочим маршрутам
- Старые `maket/LoginPage.tsx`, `maket/RegisterPage.tsx`, `maket/ResetPasswordPage.tsx` удалены
- Безопасный recovery callback без произвольных redirect URL
- Русский auth UI и основные ошибки
- `.env.example` без секретов; Service Role Key не используется
- GitHub Actions: install, typecheck, lint, format:check, production build
- CI run #73 для последнего состояния auth/макетов — успешно: все проверки и production build прошли
- `package.json` закрепляет Node.js `22.x`, чтобы Vercel не выполнял автоматический major upgrade
- Временные workflow автоматизации исправлений удалены; в `.github/workflows` остался только основной `ci.yml`
- Дизайн landing hero интегрирован в приложение
- Таблицы `products` и `product_offers` существуют в Supabase
- Для каталога включены безопасные SELECT RLS-политики: видны только активные товары и предложения активных товаров
- Есть индексы каталога, включая trigram по `products.canonical_name` и индексы связей/маркетплейсов
- `/search` переведён с демонстрационных моков на серверный поиск по Supabase
- Добавлен `src/lib/catalog/search.ts` с серверным поиском по названию, бренду, категории и описанию
- Добавлен `maket/SearchResults-v2.tsx` для отображения реальных товаров и предложений
- Если каталог пуст, UI честно показывает пустое состояние вместо фейковых товаров
- На момент проверки в каталоге: 0 товаров, 0 предложений

Безопасность:

- Service Role Key не используется в Next.js-приложении
- Токены не сохраняются вручную в localStorage или собственных cookies
- `/dashboard` защищён middleware и дополнительной серверной проверкой
- Recovery callback принимает только фиксированный внутренний переход `/reset-password`
- Ответ восстановления не раскрывает существование аккаунта
- Каталог доступен на чтение только для активных сущностей через RLS; клиентские INSERT/UPDATE/DELETE-политики не открыты

Окружение:

- Проект не запускается локально; целевая проверка — Vercel Preview.
- CI использует `npm install`.
- Для регистрации и восстановления в Supabase нужен Email provider и Redirect URLs Vercel Preview.
- Production-домен `wobuy.ru` пока не подключён к Vercel.
- Прямой Vercel-коннектор в текущей сессии недоступен; deployment проверяется через GitHub status. Последний Preview имеет статус `success`.

Текущий этап: Неделя 1–2 — каркас + Auth + лендинг + базовый реальный поиск. CI стабилен, Vercel Preview успешен. Для полного пользовательского auth flow нужна ручная проверка письма подтверждения и recovery-ссылки в Vercel Preview.

Следующий этап: слой сбора данных маркетплейсов и нормализация предложений; затем полнотекстовое ранжирование/pgvector и AI-агенты. После появления реальных данных — расширить V2-выдачу фильтрами, AI Score, историей цен и анализом отзывов.
