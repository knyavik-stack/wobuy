# Текущий статус проекта

Дата: 4 сентября 2026

Статус: Рабочая email/password авторизация Supabase Auth + восстановление пароля + выход из аккаунта реализованы поверх SSR-инфраструктуры.

Готово:

- Next.js 15 + App Router
- TypeScript
- Tailwind CSS
- ESLint + Prettier
- `@supabase/ssr` 0.12.5 и `@supabase/supabase-js` 2.115.0
- Браузерный и серверный Supabase-клиенты
- Cookie-based SSR
- Middleware с `auth.getClaims()`
- Защита `/dashboard` через middleware
- Рабочий `/login` через `signInWithPassword`
- Рабочий `/register` через `signUp` с email confirmation
- `/auth/callback` для PKCE/OAuth code exchange, email `token_hash` и безопасного перехода на `/reset-password`
- `/dashboard` с серверной проверкой пользователя
- Кнопка «Выйти» через Supabase `signOut`
- `/forgot-password` с `resetPasswordForEmail`
- `/reset-password` с проверкой активной сессии и `updateUser({ password })`
- Recovery flow использует PKCE и безопасный callback без произвольных redirect URL
- `/login`, `/register`, `/forgot-password`, `/reset-password` остаются публичными; middleware защищает только приватные маршруты
- Минимальные shadcn/ui-компоненты для auth UI
- Русские сообщения об основных ошибках авторизации
- `/login` содержит ссылку на восстановление пароля
- `.env.example` только с `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- RLS-ready структура без выдуманной схемы данных
- Runtime Node.js `>=22.0.0`
- Секреты и привилегированные ключи в репозиторий не добавлялись
- GitHub Actions CI workflow в `.github/workflows/ci.yml`: install, typecheck, lint, format:check и production build для push/PR в `main`

Безопасность:

- Service Role Key не используется в Next.js-приложении
- Токены не сохраняются вручную в localStorage или собственных cookies
- Приватный маршрут проверяется через claims в middleware и дополнительно через `getUser()` в dashboard
- Callback принимает только фиксированный внутренний `next=/reset-password`; произвольный внешний redirect невозможен
- Запрос восстановления пароля использует нейтральный ответ, не раскрывающий наличие аккаунта
- Конкретные RLS-политики будут добавляться вместе с реальной схемой таблиц

Проверка и окружение:

- Проект не запускается локально; целевой способ проверки — Vercel Preview.
- GitHub Actions CI настроен и запускается автоматически при push/PR в `main`; первый запуск пустого workflow завершился ошибкой, после чего workflow был заполнен полноценными проверками.
- `package-lock.json` в репозитории отсутствует, поэтому CI использует `npm install`, а не `npm ci`; npm cache также не включён.
- Для регистрации и восстановления в Supabase должен быть включён Email provider.
- В Supabase Auth → URL Configuration нужно добавить Redirect URLs для Vercel Preview. Для recovery используется `/auth/callback?next=/reset-password`, а callback затем переводит пользователя на `/reset-password`.
- Production-домен `wobuy.ru` пока не подключён к Vercel; после подключения нужно добавить соответствующие production Redirect URLs.

Следующий шаг: проверить результат нового CI-запуска и полный auth flow на Vercel Preview, затем подключить production-домен и пользовательские данные с RLS-политиками.
