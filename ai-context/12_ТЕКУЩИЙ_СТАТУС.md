# Текущий статус проекта

Дата: 5 сентября 2026

Статус: фундамент проекта, Supabase Auth, демо-каталог, UI и CI стабилизируются. Работа продолжается в режиме полной механической ревизии.

## Готово

- Next.js 15 + App Router, TypeScript, Tailwind CSS, ESLint + Prettier
- Supabase SSR/Auth с реальными login/register/recovery/reset сценариями
- Защита `/dashboard`, RLS пользовательских данных
- Демо-каталог: 12 товаров, 16 предложений
- `/search` подключён к Supabase
- `/product/[id]`, `/dashboard`, `/privacy`, `/terms`
- Loading/error states и тёмный 404
- Главная с рабочими якорями и поиском
- Старый `maket/SearchResults.tsx` удалён; каноничный макет — `SearchResults-v2.tsx`
- V2 выдачи очищена от старого `createClient` и лишних ESLint-проблем
- Фильтры выдачи переработаны в компактную панель категории + сортировка
- Добавлено переключение вида каталога: карточки 3 в ряд на desktop или список; выбор сохраняется в URL `view`
- Добавлен favicon через `src/app/icon.svg`
- Добавлены полноценные metadata title/description и шаблон заголовков
- Убрана лишняя auth-панель из общего auth-layout
- Базовый UI рассчитан на тёмный фон
- Последний проверенный GitHub Actions run `33916390080` успешен: TypeScript, ESLint, форматирование и production build прошли

## Безопасность

- Service Role Key не используется в клиенте
- Токены не сохраняются вручную в localStorage/собственных cookies
- `/dashboard` защищён middleware и серверной проверкой
- Recovery callback использует фиксированный внутренний переход
- Пользовательские таблицы ограничены через `auth.uid()` RLS
- Ingestion требует JWT и `app_metadata.ingestion_enabled=true`
- Демо-данные не содержат реальные учётные данные маркетплейсов

## Окружение

- Проект работает через GitHub Actions и Vercel, локальный production-запуск не используется.
- Прямого Vercel-коннектора в текущей сессии нет.
- Vercel ранее возвращал `Deployment rate limited — retry in 24 hours`; это ограничение deployment, а не ошибка CI-кода.

## Текущий этап

Полная механическая ревизия: визуальная плотность, скролл, auth, каталог, кнопки, ссылки, мобильный UX, состояния ошибок и доступность действий.

Следующая обязательная проверка — новый CI после последних изменений. Не считать работу завершённой до его успешного завершения.
