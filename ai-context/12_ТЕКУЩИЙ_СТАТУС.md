# Текущий статус проекта

Дата: 4 сентября 2026

Статус: Базовый каркас Next.js 15 создан, Supabase Auth подключён на уровне SSR-инфраструктуры.

Готово:
- Next.js 15 + App Router
- TypeScript
- Tailwind CSS
- ESLint + Prettier
- Базовая структура `src/app`, `src/components`, `src/lib`, `public`
- `@supabase/ssr` 0.12.5 и `@supabase/supabase-js` 2.115.0
- Браузерный Supabase-клиент через `createBrowserClient`
- Серверный Supabase-клиент через `createServerClient` и Next.js cookies API
- `src/middleware.ts` для обновления Supabase-сессии через `auth.getClaims()`
- Cookie-based SSR без ручного хранения токенов в localStorage или собственных cookies
- Заготовки страниц `/login` и `/register`
- `.env.example` только с именами разрешённых переменных окружения
- Базовая документация `supabase/README.md` для RLS и будущих миграций
- Runtime Node.js поднят до `>=22.0.0` с учётом актуальной поддержки Supabase SDK
- Секреты и привилегированные ключи в репозиторий не добавлялись

Безопасность:
- Используются только `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- Service Role Key не используется в Next.js-приложении
- Авторизация не доверяет `getSession()` для серверных решений доступа; middleware валидирует claims
- RLS подготовлен архитектурно; политики будут добавляться вместе с реальной схемой БД

Ограничение текущего этапа:
- Фактические npm install/build/lint/typecheck через удалённый GitHub-коннектор не выполнялись, поэтому CI-сборка отдельно не подтверждена.

Следующий шаг: реализовать реальный login/register flow и после появления схемы данных добавить конкретные RLS-политики.
