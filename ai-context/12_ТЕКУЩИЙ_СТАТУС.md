# Текущий статус проекта

Дата: 4 сентября 2026

Статус: фундамент проекта, Supabase Auth, базовый каталог и CI стабилизированы. Перешли в режим полной эмуляции продукта: каталог наполнен демонстрационными товарами и предложениями, чтобы отладить пользовательские сценарии до подключения реальных API маркетплейсов.

Готово:

- Next.js 15 + App Router, TypeScript, Tailwind CSS, ESLint + Prettier
- Framer Motion для интерфейсной анимации
- Supabase SSR: browser/server clients, cookie-based SSR
- Email/password login и register с подтверждением email
- `/auth/callback` для PKCE/OAuth и recovery
- Защита `/dashboard`, серверная проверка пользователя и logout
- `/login`, `/register`, `/forgot-password`, `/reset-password`
- `/auth/login`, `/auth/register`, `/auth/reset` как совместимые redirect-маршруты
- V2 auth-дизайн подключён к рабочим маршрутам
- V2 login использует реальный Supabase Auth без имитации задержки
- Единая ссылка на главную в auth-layout; логотипы ведут на `/`
- Старые auth-макеты первой версии удалены
- Безопасный recovery callback без произвольных redirect URL
- `.env.example` без секретов; Service Role Key не используется в клиенте
- Основной CI: format → typecheck → lint → format:check → production build
- Отдельный workflow автоформатирования удалён: форматирование не создаёт второй CI-процесс
- Node.js `22.x` закреплён в проекте
- Таблицы `products`, `product_offers`, `ingestion_runs` существуют в Supabase
- RLS и индексы каталога настроены
- `/search` подключён к Supabase
- Создан `/product/[id]` с карточкой товара и предложениями
- Добавлены `/privacy` и `/terms`
- Демо-каталог наполнен 12 товарами и 16 предложениями
- Главная: навигация «Как это работает», «Тарифы», «О нас» ведёт на реальные секции
- Главная: «Найти лучшее» и «Посмотреть подборку» запускают выдачу
- Верхняя часть главной больше не обрезается по вертикали: контейнер ограничивает только горизонтальный overflow
- Добавлены таблицы пользовательского рабочего пространства: избранное, сохранённые поиски, история просмотров, демо-история цен
- RLS для пользовательских данных ограничивает доступ текущим пользователем
- Карточка товара умеет сохранять товар в избранное и записывает просмотр в историю
- Демо-кабинет показывает избранное, сохранённые поиски, историю и настройки
- Поиск получил фильтр категорий, сортировку по цене/рейтингу и демо-аналитику результата
- Демо-аналитика показывает количество товаров, предложений, средний рейтинг и диапазон цен

Безопасность:

- Service Role Key не используется в клиентском коде
- Токены не сохраняются вручную в localStorage или собственных cookies
- `/dashboard` защищён middleware и серверной проверкой
- Recovery callback принимает только фиксированный внутренний переход `/reset-password`
- Каталог доступен на чтение только для активных сущностей через RLS
- Пользовательские таблицы используют `auth.uid()` в RLS
- Ingestion Edge Function требует JWT и `app_metadata.ingestion_enabled=true`
- Демоданные не используют реальные учётные данные маркетплейсов

Окружение:

- Проект не запускается локально; целевая проверка — GitHub Actions и Vercel Preview.
- CI использует `npm ci` и Node.js 22.
- Production-домен `wobuy.ru` пока не подключён к Vercel.
- Прямой Vercel-коннектор в текущей сессии недоступен; deployment проверяется через GitHub status.

Текущий этап: полная эмуляция продукта до подключения маркетплейсов. Приоритет — закончить механическую проверку сайта и кабинета: меню, ссылки, формы, состояния кнопок, поиск, карточки товара, внешние переходы, сохранение, история, фильтры и ошибки.

В работе:

- Полная механическая проверка всех пользовательских сценариев
- Настройки кабинета как полноценный пользовательский раздел
- Loading/error/empty states и единая навигация
- Проверка всех мёртвых ссылок и кнопок

Не начинали:

- Реальные API Ozon/Wildberries/Яндекс Маркета
- Полнотекстовое и семантическое ранжирование
- pgvector и embeddings
- AI-агенты анализа товаров/отзывов

Следующий шаг после полной отладки демо: подключить реальные API маркетплейсов к уже подготовленному ingestion-контру без изменения пользовательского сценария.
