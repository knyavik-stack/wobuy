# История промптов

## 2026-09-04

### Создание базового каркаса проекта

Задача: создать базовый каркас WOBuy на Next.js 15 с App Router, TypeScript, Tailwind CSS, ESLint и Prettier; добавить README.md, проверить `/ai-context/`, не добавлять секреты и обновить статус, changelog и историю промптов.

Результат: каркас создан и подготовлен к дальнейшей разработке.

### Подключение Supabase Auth

Задача: подключить Supabase Auth максимально безопасно через официальный `@supabase/ssr`, создать browser/server clients, настроить cookie-based SSR, подготовить login/register и RLS без секретов.

Результат: добавлены клиенты Supabase, middleware с `auth.getClaims()`, auth-заготовки, `.env.example` и RLS-документация. Версии `@supabase/ssr` 0.12.5 и `@supabase/supabase-js` 2.115.0 закреплены в `package.json`; минимальный Node.js — 22.0.0. Service Role Key и другие секреты не добавлялись.

### Реализация рабочего login/register flow

Задача: сделать email/password авторизацию рабочей, добавить callback для подтверждения email и OAuth, защитить `/dashboard`, сделать современный русский auth UI и обработку ошибок.

Результат: `/login` использует `signInWithPassword`, `/register` использует `signUp` с email confirmation, `/auth/callback` обрабатывает PKCE/OAuth code и email `token_hash`, middleware защищает `/dashboard`, добавлены минимальные shadcn/ui-компоненты. Секреты не добавлялись.

### Выход и восстановление пароля

Задача: добавить полноценный logout, `/forgot-password`, `/reset-password`, русские ошибки и современный UI; сохранить публичность auth-страниц и обновить документацию.

Результат: на `/dashboard` добавлена кнопка «Выйти» через `signOut`; `/forgot-password` отправляет recovery-письмо через `resetPasswordForEmail`; `/reset-password` устанавливает новый пароль через `updateUser`; существующий callback расширен безопасным фиксированным `next=/reset-password`; middleware продолжает защищать только приватные маршруты. Ответ recovery нейтрален и не раскрывает наличие аккаунта. Секреты не добавлялись.

### Настройка GitHub Actions CI

Задача: самостоятельно создать и настроить `.github/workflows/ci.yml`, чтобы проект автоматически проверялся на push и pull request в `main`, а также обновить обязательную документацию проекта.

Результат: workflow настроен на Node.js 22 и выполняет `npm install`, `npm run typecheck`, `npm run lint`, `npm run format:check` и `npm run build`. Так как `package-lock.json` отсутствует, используется `npm install`, без `npm ci` и npm cache. Первый запуск пустого workflow завершился ошибкой; затем workflow был заменён на полноценную конфигурацию. Обновлены `12_ТЕКУЩИЙ_СТАТУС.md` и `changelog.md`.
