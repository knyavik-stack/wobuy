# История промптов

## 2026-09-04

### Создание базового каркаса проекта

Задача: создать базовый каркас на Next.js 15 с App Router, TypeScript, Tailwind CSS, ESLint и Prettier.

Результат: каркас создан и подготовлен к дальнейшей разработке.

### Подключение и реализация Supabase Auth

Задача: безопасно подключить Supabase Auth, сделать email/password login/register, confirmation, callback, защиту dashboard, logout и восстановление пароля.

Результат: auth flow реализован через `@supabase/ssr`, middleware и cookie-based SSR; добавлены `/login`, `/register`, `/auth/callback`, `/dashboard`, `/forgot-password`, `/reset-password`.

### Стабилизация CI/CD

Задача: довести CI до зелёного состояния, устранить предупреждение Node.js на Vercel и убрать временную автоматизацию.

Результат: CI run #60 полностью успешен; Node.js закреплён на `22.x`; временные workflow удалены.

### Перевод auth UI на V2

Задача: использовать только утверждённые V2-макеты и устранить 404 на auth-маршрутах.

Результат: `/login`, `/register`, `/forgot-password`, `/reset-password` подключены к V2; добавлены совместимые `/auth/login`, `/auth/register`, `/auth/reset`; старые `maket/LoginPage.tsx`, `maket/RegisterPage.tsx`, `maket/ResetPasswordPage.tsx` удалены. Восстановление пароля переведено с имитации на реальный Supabase `resetPasswordForEmail` + `updateUser`.

### Реальный каталог и поиск

Задача: убрать демонстрационные товары из поисковой выдачи и подключить `/search` к реальному слою данных.

Результат: добавлен серверный `searchProducts()` для Supabase `products` + `product_offers`, создан `maket/SearchResults-v2.tsx`, маршрут `/search` принимает `?q=` и показывает только активные реальные данные. Пустой каталог отображается без фейковых товаров. RLS и индексы каталога проверены.

### Системное устранение проблем форматирования

Задача: исключить повторяющиеся красные CI из-за Prettier и автоматически поддерживать единый формат во всём репозитории.

Результат: добавлен единый `npm run format`, CI форматирует проект перед проверками, а постоянный `.github/workflows/format.yml` автоматически применяет и сохраняет Prettier-исправления. CI run #82 успешно завершён.

### Основа ingestion-пайплайна

Задача: подготовить безопасный слой для загрузки и дедупликации реальных предложений маркетплейсов.

Результат: добавлена таблица `ingestion_runs`, уникальность `marketplace + external_id` для предложений, вычисляемый `canonical_key` для товаров и защищённая Edge Function `ingest-catalog`. Функция принимает только разрешённые источники, валидирует данные, пишет журнал загрузки и выполняет upsert в каталог. Доступ разрешён только JWT-пользователям с `app_metadata.ingestion_enabled=true`.

Следующая задача: подключить реальные адаптеры Ozon/Wildberries/Яндекс Маркета, затем завершить нормализацию и повторные загрузки; после наполнения каталога — полнотекстовое/семантическое ранжирование, pgvector и AI-агенты.
