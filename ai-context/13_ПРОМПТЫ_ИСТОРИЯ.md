# История промптов

## 2026-09-05

### UX ревизия главной, auth и каталога

Задача: устранить визуальные белые поля, лишнее пространство в auth, повторяющиеся проблемы выдачи и улучшить UX каталога.

Результат: auth-layout очищен от дублирующей панели; верхний воздух над логотипом auth уменьшен; добавлен favicon; metadata получили нормальный title/description; V2 выдача очищена от старого макета и лишних импортов; фильтры собраны в компактную раскрывающуюся панель; добавлены два режима desktop-каталога — 3 карточки в ряд и список; выбор вида сохраняется через URL; hero уплотнён, фоновые glow-эффекты не расширяют страницу; документ получил единый тёмный фон и защиту от горизонтального overflow.

### Навигация по якорям

Задача: при переходе по «Как это работает», «Тарифы» и «О нас» fixed header не должен закрывать верхнюю часть целевой секции.

Результат: нативный переход по hash заменён на программный `scrollTo` с фиксированным offset 80px; мобильная навигация использует тот же механизм и автоматически закрывается после выбора секции.

### CI контроль

Предыдущее красное сообщение про `createClient` относится к старому состоянию. Проверенный run `33916390080` завершился успешно: TypeScript, ESLint, форматирование и production build прошли. После последних изменений требуется новый CI-прогон и он является обязательной точкой контроля.

## 2026-09-04

### Создание базового каркаса проекта

Задача: создать базовый каркас на Next.js 15 с App Router, TypeScript, Tailwind CSS, ESLint и Prettier.

Результат: каркас создан и подготовлен к дальнейшей разработке.

### Подключение Supabase Auth

Задача: безопасно реализовать email/password login/register, confirmation, callback, защиту dashboard, logout и восстановление пароля.

Результат: auth flow реализован через `@supabase/ssr`, middleware и cookie-based SSR.

### Перевод auth UI на V2

Задача: использовать утверждённые V2-макеты.

Результат: auth-маршруты подключены к V2, recovery использует реальный Supabase flow.

### Реальный каталог и поиск

Задача: подключить `/search` к Supabase вместо демонстрационных моков.

Результат: серверный `searchProducts()` и V2-выдача на базе `products` + `product_offers`.

### Переход на полную демо-эмуляцию

Задача: не ждать API маркетплейсов, а отладить продукт на контролируемых демонстрационных данных.

Результат: Supabase-каталог наполнен 12 демонстрационными товарами и 16 предложениями.

### Механическая ревизия

Задача: устранить мёртвые действия, повторяющиеся CI-ошибки, проблемы навигации и нестабильные пользовательские сценарии.

Результат: регистрация V2 переведена на реальный Supabase Auth; добавлены loading/error states, 404, рабочие избранное/история/настройки; главная и поиск получили рабочую механику.
